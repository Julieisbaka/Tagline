08 Developer reference

Build a Tagline extension.

Extend the workspace with commands, settings, themes, and sandboxed UI. Declare only the permissions your extension needs and use the provided bridge instead of accessing app internals.

Install and reload

  1. Open Settings > Extensions > Open extensions folder.
  2. Create a subfolder containing manifest.json and its referenced files.
  3. Select Reload extensions, review the requested permissions, and enable the extension.
  4. Find contributed commands in the command palette (Mod+P) and themes in Settings > Appearance > Theme.

Extensions live in the app profile, not in a vault. Reload after changing extension files. Reloading recreates enabled script hosts; disabling removes the host and its contributions but does not explicitly delete its private stored data.

Entry scripts run in a sandboxed worker with the supplied tagline bridge. They are async function bodies, not ES modules: top-level await works, but top-level import/export and CommonJS require do not. Bundle dependencies into a self-contained script.

First-install setup

Register at most one tagline.onInstall(handler) synchronously while the entry script initializes. Tagline awaits it before marking the host ready. Use idempotent setup: an interrupted callback may run again on the next load. Successful setup is remembered by extension ID, so ordinary reloads, updates, and disable/re-enable do not repeat it. Theme-only extensions do not have this hook. 

tagline.onInstall(async () => {
  if (!(await tagline.storage.get('installedAt'))) {
    await tagline.storage.set('installedAt', new Date().toISOString());
  }
  await tagline.webviews.setHtml(
    'welcome',
    '<h2>Welcome!</h2><p>Configure this extension in Settings.</p>',
  );
  await tagline.webviews.show('welcome');
});

This example needs ui permission and a declared welcome webview. Entry evaluation and setup share the startup deadline (10 seconds by default); show onboarding and return rather than waiting for the user to finish it.

Browse and publish extensions

Settings > Extensions > Browse extensions lists community extensions from the Tagline extension registry. Tagline contacts GitHub only after you select Browse registry. Each card shows the name, version, authors, description, permissions, and network hosts read from the extension's manifest.json. Installed extensions show Installed, or Update to vX when the registry version differs.

Installing resolves the listed ref to a commit, downloads only the files in that folder, checks every file against its Git blob hash, then uses the same validation, size limits, and permission review as installing from a folder. Registry extensions are not reviewed by Tagline; install only extensions you trust.

Submit an extension

  1. Publish the extension folder (with manifest.json at its root) in a public GitHub repository. Declare authors and sourceUrl so users can see who maintains it.
  2. Open a pull request that appends its URL to extensions/registry.json: 
{
  "version": 1,
  "extensions": [
    { "url": "https://github.com/you/tagline-word-count" },
    { "url": "https://github.com/you/tools/tree/v1.2.0/word-count" }
  ]
}

Use https://github.com/owner/repo for the default branch root, or https://github.com/owner/repo/tree/<ref>/<folder> for a tag, branch, or commit and a subfolder. The ref cannot contain /. Pointing at a tag pins users to a reviewed release; pointing at a branch lets users update when you push. Each extension id may appear only once. A pull-request check validates the file against schemas/extension-registry.schema.json and loads every listed manifest.

Review before enabling

Enabling an extension that declares any of these capabilities requires an explicit review of its manifest:

  • settings
  • editor:active-note
  • events
  • ui
  • network
  • secrets

Tagline computes a review signature from the manifest’s declared permissions (sorted), network hosts, settings, ribbon items, panels, and webviews, then derives a SHA-256 token from that value. Reloading extensions recomputes the token and compares it with the stored approval. Changing any reviewed field invalidates the approval; for example, adding network or secrets, changing networkHosts, or changing a declared setting requires a new review.

Only Settings > Extensions can enable or approve an extension, and enabling requires the token for its current manifest. A missing or stale token is rejected with Extension permissions or settings changed. Reload and review before enabling. After a successful enable, the approval signature is stored in extensionReviews in the app’s config.json. On every launch and reload, Tagline scans each manifest and checks its stored approval again.

If an approval no longer matches, the extension is treated as disabled: its host does not start, its commands are unavailable, and its selectable themes fall back to the default palette until you review and enable it again. Extensions that declare a gated capability but have no stored approval—including extensions installed before reviews were introduced—also need review. The native menu can open Settings > Extensions only; it cannot enable or approve an extension.

An extension declaring network must also declare networkHosts, a list of exact lowercase hostnames. Tagline includes this list in the review signature and shows it in Settings > Extensions. Review the requested hosts before approving the extension.

A minimal command extension

Create an extension folder with a manifest and one entry script:

debate-tools/
  manifest.json
  main.js
{
  "manifestVersion": 1,
  "id": "debate-tools",
  "name": "Debate Tools",
  "version": "0.1.0",
  "description": "Insert a reminder into the active note.",
  "authors": ["Example Author"],
  "sourceUrl": "https://github.com/example/debate-tools",
  "main": "main.js",
  "permissions": ["editor"],
  "contributes": {
    "commands": [
      { "id": "insert-reminder", "title": "Insert evidence reminder", "key": "Mod+Alt+K" }
    ]
  }
}
await tagline.commands.register('insert-reminder', async () => {
  const note = await tagline.editor.getActiveNote();
  if (!note || !/\.md$/i.test(note.path) || note.mode === 'read') {
    await tagline.notify('Open a Markdown note in an editing mode first.');
    return;
  }
  await tagline.editor.insertText(
    '\n\nVerify author, date, and source before use.\n',
  );
});

The command appears as Debate Tools: Insert evidence reminder; its internal application ID is ext:debate-tools.insert-reminder. Register and await every contributed command during initialization.

Manifest reference

Field Requirement

main Relative path to a .js file when commands or script contributions are used; optional for theme-only extensions.

networkHosts Required when permissions includes network. List the exact lowercase hostnames the extension needs; the list is reviewed and included in the approval signature.
contributes.commands Up to 50 declarations; each has a unique ID and nonblank title (up to 80 characters). Requires main.
contributes.themes Up to 20 relative .json paths.
contributes.settings Up to 32 typed settings; requires settings permission.
contributes.panels, contributes.webviews Up to 10 { id, title } declarations each; require ui permission and main.
contributes.ribbonItems Up to 10 { id, title, icon, command } shortcuts; requires ui and a declared command. Unknown icon names use the file icon.

Contribution IDs use the extension-ID character rules. Paths must remain inside the extension folder; absolute paths, traversal, and symlinks resolving outside it are rejected. Default file limits are 1 MiB for scripts and 64 KiB per contributed theme. The aggregate JSON size of theme files loaded from one extension is limited to 524,288 bytes by default; this Theme preview bytes limit can be adjusted from 1,024 to 4,194,304 bytes. Per-file limits apply independently. Limits are adjustable within fixed bounds in Settings > Advanced settings > Theme and extension limits.

Invalid manifests and load failures are shown in extension settings. A script must finish initialization within 10 seconds. See the JSON formats guide for schema validation and editor completion.

Permissions and isolation

Permission Grants
editor Read the active note and selection; insert text, set selection, and run approved Tiptap commands. Reading a note exposes its entire content.
editor:active-note Subscribe to active-note path changes only, without content or selection access. Does not imply editor.
settings Read and write only this extension's declared, validated settings.
vault:read List and read loaded .md, .flow, and .canvas documents; watch changes.
vault:write Create, replace, rename, trash, and flush supported notes. Append and compare-and-swap also require vault:read.
events Subscribe to application events (plus each event's data permission) and namespaced custom events; emit events only in this extension's namespace.
ui Display declared ribbon shortcuts, panels, and webviews; exchange messages with those surfaces.
network Use tagline.network.fetch() for host-mediated HTTPS GET/POST requests to hosts declared in networkHosts.
secrets Read, store, check, and delete OS-encrypted secret strings scoped to this extension ID. Requires review; see Encrypted secrets.
None Register declared commands, notify the user, use private extension storage, and contribute JSON themes.

Undeclared permission checks reject API calls. For every network request, the main process rechecks that the extension is enabled and its manifest still declares the permission and requested host. Requests reject local or private DNS results, embedded URL credentials, non-HTTPS schemes, non-default ports, cookies, automatic redirects, and compressed responses. Requests are limited to 10 per second, request and response bodies of 1,000,000 bytes each, and a 15-second timeout. The extension worker and webviews have no direct network access. Extensions also have no direct Node.js, Electron API, application DOM, profile storage, or arbitrary filesystem access. See Review before enabling for the manifest approval required for gated capabilities.

  • Workers keep synchronous extension loops off the application UI thread. A supervisor stops a worker that misses heartbeats for 5 seconds; startup has a 10-second deadline.
  • More than 200 messages in a rolling second stops an extension. At most 32 bridge calls may be pending, and each extension may register up to 32 vault watches and 32 active-note listeners.
  • Nested Worker and SharedWorker constructors are disabled. Disable, reload, or unload tears down the worker.

Runtime failures appear in notifications and startup failures on the extension card. Await bridge calls and handle specific errors where you can explain recovery; unhandled command errors are surfaced to the user.

Commands and editor

Bridge methods return promises. Command handlers receive no arguments and expose no return value to the host. 

await tagline.commands.register(id, handler);
await tagline.notify(message);

const note = await tagline.editor.getActiveNote();
// null or { path, content, selection, selectionRange, editorKind, mode, kind }
await tagline.editor.insertText(markdown);
await tagline.editor.setSelection({ from: 1, to: 12 });
const snapshot = await tagline.editor.tiptap.getSnapshot();
await tagline.editor.tiptap.runCommand('toggleBold');

Notifications accept strings up to 500 characters and include the extension name. The active-note snapshot includes vault-relative path, current content (including unsaved edits), selected text, and editor state. Modes are visual, edit, or read; kinds are markdown, flow, or canvas. Content is available only with editor.

insertText requires an open Markdown note in an editing mode and a ready editor. In visual mode it parses Markdown; in source mode it inserts literal text. It replaces the selection or inserts at the cursor and schedules normal autosaving. It rejects in reading mode or on a flow, and accepts up to 5,000,000 characters.

Selection offsets are source-character offsets starting at 0 in source mode and ProseMirror positions in visual mode (text usually starts at 1); the coordinate systems are not interchangeable. Invalid or out-of-document positions reject. Tiptap snapshots and commands require an active visual Markdown editor; reading mode, flows, and source fallback reject.

Approved Tiptap commands are toggleBold, toggleItalic, toggleUnderline, toggleHighlight, toggleStrike, toggleHeading, setParagraph, toggleBulletList, toggleOrderedList, toggleBlockquote, undo, redo, and unsetAllMarks. Only toggleHeading accepts options: { level: 1..6 }.

Use tagline.editor.onActiveNoteChanged(callback) with the separate editor:active-note permission to subscribe to { path } changes only. It does not provide an initial snapshot; call getActiveNote() only when full editor access is needed and approved. Unloading the extension unsubscribes automatically.

Application event bus

Every subscription requires events. Built-in events also require the listed data permission. Subscriptions do not replay initial state and are removed on disable, reload, or worker failure.

Event Additional permission Payload
vault.changed vault:read { open: boolean }, when the open vault changes.
vault.fileChanged vault:read Path-only change/reset events, like vault.watch.
note.changed editor:active-note { path: string | null }.
editor.updated editor { path, mode }, on content, note, or mode changes.
editor.selectionChanged editor { mode, selection: { from, to }, path? }.
editor.ready editor { mode, path? }. 
const stop = await tagline.events.on(
  'editor.selectionChanged',
  async (event) => {
    await tagline.storage.set('last-selection', event.selection);
  },
);
await stop();

Custom event names follow ext.<extension-id>.<event-name>. Extensions may listen to other namespaces but can emit only in their own. Names are limited to 128 characters; custom event and UI-message payloads must be JSON-serializable and no larger than 65,536 characters. Treat payloads from other extensions as untrusted.

Panels, webviews, and UI

Declare surfaces before using them. IDs use command-ID syntax; titles are nonblank and at most 80 characters. Each surface belongs to its extension. 

{
  "permissions": ["ui"],
  "main": "main.js",
  "contributes": {
    "panels": [{ "id": "research-panel", "title": "Research" }],
    "webviews": [{ "id": "source-details", "title": "Source details" }]
  }
}
tagline.webviews.onMessage('source-details', async (message) => {
  if (message.ready) {
    await tagline.webviews.postMessage('source-details', {
      title: 'Example source',
    });
  }
});
await tagline.webviews.setHtml(
  'source-details',
  '<h1 id="title"></h1><script>' +
    'taglineWebview.onMessage(m => {' +
    'document.getElementById("title").textContent = m.title;' +
    '}); taglineWebview.postMessage({ ready: true });</script>',
);
await tagline.webviews.show('source-details');

Register message handlers before showing the surface. The page should send a ready message after registering its handler; posting to an unmounted surface rejects. setHtml replaces the page, show displays it, and close hides/unmounts it while retaining HTML for reopening. Disabling or reloading removes contributed surfaces.

Panels appear above the built-in right sidebar; webviews appear as dialogs. HTML is limited to 200,000 characters and runs in an opaque-origin sandbox="allow-scripts" iframe without same-origin access, Node, Electron APIs, network requests, forms, nested frames/workers, popups, or arbitrary navigation. Styles must be inline; images may use data URLs. Never inject unescaped note content; use textContent. Webview scripts have DOM access and can still block renderer responsiveness if they do expensive synchronous work.

Theme-aware UI kit

Panels and webviews receive app colors, fonts, selection colors, and a shared control stylesheet. Prefer taglineUI factories to hardcoded colors: 

const ui = taglineUI;
document.body.append(
  ui.card({
    title: 'Research',
    children: [
      ui.field({ label: 'Filename', onChange: (value) => {} }),
      ui.select({
        label: 'Side',
        value: 'aff',
        options: [{ label: 'Affirmative', value: 'aff' }],
      }),
      ui.toggle({ label: 'Include flows', checked: true, onChange: () => {} }),
      ui.notice({ text: 'Ready', tone: 'info' }),
      ui.button({ label: 'Search', variant: 'primary', onClick: () => {} }),
    ],
  }),
);

Factories return native elements with labels, keyboard behavior, focus indicators, and reduced-motion support. Available controls include stack, card, field, select, toggle, notice, and button. Text and labels are inserted as text, not HTML. In webviews, taglineWebview.getTheme() returns the current theme and onThemeChange(callback) observes updates; see the Theme API.

Helpers and disposable subscriptions

Pure helpers require no permission. Path helpers normalize vault-relative paths and reject absolute paths or traversal above the vault root; they do not access files. 

const path = await tagline.helpers.path.join('Research', 'Energy.md');
const text = await tagline.helpers.markdown.toText('**Evidence**');
const outline = await tagline.helpers.markdown.outline('# Case\n\n#### Card');
const html = await tagline.helpers.markdown.toHtml('**Safe**');
const metadata = await tagline.helpers.markdown.frontmatter(markdown);
const tags = await tagline.helpers.markdown.extractTags(markdown);
const card = await tagline.helpers.cards.getAt(markdown, 0);
const stats = await tagline.helpers.cards.stats(card.text);
const timing = await tagline.helpers.speech.estimate(card.text, 250);
const citation = await tagline.helpers.citations.create({ author: 'Smith', year: '2024' });
const filled = await tagline.helpers.templates.fill('Case: {{title}}', 'Energy');
  • Markdown: toText, toHtml (sanitized), frontmatter, slugify, outline, extractLinks, extractTags, and resolveLink(target, paths). Frontmatter returns { data, body, prefix }; invalid YAML rejects. Outline line numbers are zero-based and include frontmatter lines.
  • Cards and speech: cards.getAt, cards.stats, cards.spokenEvidence, cards.formatDuration, speech.analyze, and speech.estimate(text, wordsPerMinute = 250).
  • Other helpers: templates.fill, citations.create, search.fuzzyScore, countdown.remainingAt, language.system/initial, keybindings.valid/display, and layout normalization/movement helpers.
  • Structured data: canvas and flow parse/serialize/create helpers; folder path normalization; frontmatter and speech-path helpers; calendar date/grid helpers; vault path/index/link helpers; and NLI premise, hypothesis, and label helpers.
Namespace Pure helper methods

templates.fill(template, title, context) recognizes {{date}}, {{time}}, {{title}}, {{path}}, {{content}}, and {{properties}}. Pass a target vault-relative path and full Markdown content in context; content expands to the body without frontmatter and properties to the original YAML without delimiter lines. Values substitute literally in one pass, omitted values become empty strings, and unknown placeholders remain unchanged.

Additional bounds include 10,000 supplied paths for link resolution; 10,000 document paths and 1,000,000 total text characters; 1,000 entries for layout catalogs and ID arrays; 10,000 folder-tree nodes and 100 levels; and 100,000 flow cells. Speech estimates accept 50–1,000 words per minute, and calibration accepts up to 100 validated samples.

Invalid or oversized inputs reject rather than being silently truncated. Markdown rendering, text, links/tags, card analysis, and speech timing exclude frontmatter; link and tag extraction skip fenced and inline code.

Typed extension settings

Declare settings permission and typed contributions. This is a manifest fragment; include the required manifest fields as well. 

{
  "permissions": ["settings"],
  "contributes": {
    "settings": [
      { "id": "enabled", "title": "Enable reminders", "type": "boolean", "default": true },
      { "id": "limit", "title": "Result limit", "type": "number", "min": 1, "max": 20, "default": 5 },
      { "id": "style", "title": "Style", "type": "string", "enum": ["brief", "full"], "default": "brief" }
    ]
  }
}
const limit = await tagline.settings.get('limit');
await tagline.settings.set('limit', 10);

Each setting has a unique ID, nonblank title (up to 80 characters), type, and valid default. Optional descriptions are limited to 500 characters. Booleans accept only booleans; numbers must be finite and may have inclusive bounds; strings default to a 1,000-character limit (configurable from 1 to 10,000) and may restrict values to 1–50 unique enum choices. Invalid definitions, undeclared IDs, and type or range mismatches reject instead of coercing values.

Users can edit, save, and reset settings on the extension card under Settings > Extensions. Settings are scoped to the extension ID and separate from private storage. They are not encrypted; do not use them for secrets. Invalid saved values surface errors and can be reset by the user.

Canvas and flow documents

tagline.canvas.read(path) and tagline.flow.read(path) parse documents and require vault:read. Their write(path, document) counterparts validate and serialize data, require vault:write, and return the saved path. Paths must end in .canvas or .flow. Saves use normal autosaving and revision history; call tagline.vault.flush() to await disk persistence.

Pure helpers require no permissions: canvas parse/serialize, node and argument-edge creation, group membership, link resolution, file suggestions, and node movement; flow parse/serialize/create and cell updates. Relations are supports, answers, or contradicts. Helpers return new values rather than mutating inputs. Canvas link resolution only considers supplied paths and never opens or reads files.

See JSON formats and schemas for flow validation and the standard JSON Canvas specification.

Vault API

const paths = await tagline.vault.list();
const content = await tagline.vault.read(path);
const actualPath = await tagline.vault.write(path, content);
await tagline.vault.append(path, text);
const renamed = await tagline.vault.rename(path, newPath);
await tagline.vault.delete(path); // moves the note to the OS trash
await tagline.vault.flush();
const changed = await tagline.vault.compareAndSwap(path, expected, replacement);
const stop = await tagline.vault.watch((event) => {});
await stop();

list, read, and watch require vault:read. Mutations and flush require vault:write; append and compareAndSwap require both. Paths are vault-relative with / separators, preserve file extensions, and are limited to 1,000 characters.

  • list returns loaded supported note paths, not arbitrary files or folders. read returns current loaded content and rejects for an absent note; reload the vault after external edits.
  • write accepts .md, .flow, and .canvas. It replaces loaded content or creates a note through the normal workflow. Folder normalization/collision handling can change a new path; use the returned path. Writes are debounced, so resolving does not mean disk persistence is complete. Content is limited to 5,000,000 characters.
  • append adds literal text to an existing note and preserves unsaved edits. compareAndSwap compares the entire loaded text, including unsaved edits, and replaces only on an exact match; mismatch returns false. Concurrent extension mutations are serialized.
  • flush waits for queued autosaves and in-flight writes for the current vault, including user edits. It rejects on save failure; edits made after it starts may require another flush.
  • rename and delete act on existing notes (not folders), flush first, and reject on save failure. Rename uses the app's normal relinking and tab updates; delete moves the note to the OS trash and closes its tabs.
  • watch reports path-only create/change/delete events or { type: 'reset' } when switching vaults. Events may be coalesced; renames appear as delete/create. Read a current snapshot separately when needed.

Private extension storage

const value = await tagline.storage.get('key'); // value or null
await tagline.storage.set('key', { enabled: true });
await tagline.storage.set('key', null); // delete the key

No permission is required. Keys are strings up to 200 characters; values should be JSON-compatible. Setting null or undefined removes a key. The total serialized object is limited to 100,000 characters. Storage is scoped by extension ID in the local app profile and survives host reloads; it is not encrypted, synced, or a vault file.

Do not store API keys or other credentials here. Use tagline.secrets for encrypted secret strings.

Encrypted extension secrets

Declare the review-gated secrets permission in manifest.json to use tagline.secrets: 

"permissions": ["secrets"]
await tagline.secrets.set('api-key', 'your-api-key'); // Promise<true>
const key = await tagline.secrets.get('api-key'); // string or null
await tagline.secrets.has('api-key'); // Promise<boolean>
await tagline.secrets.delete('api-key'); // Promise<boolean>; same as set(key, null)

Keys are non-empty strings up to 200 characters. Values are strings up to 10,000 characters, and each extension can hold up to 50 secrets. get returns null when the key is absent; has returns whether it exists. Setting null or undefined deletes the key, as does delete.

Secrets are encrypted with the operating-system credential service through Electron safeStorage in the main process and stored in <userData>/extension-secrets/<extension-id>.bin, scoped by extension ID. They are never written to the vault, settings exports, tagline.storage, or localStorage. Calls reject if OS encryption is unavailable or the extension is disabled; there is no unencrypted fallback.

Users can remove an extension's secrets with Clear stored secrets on its card in Settings > Extensions. Disabling an extension blocks access but does not clear its stored secrets.

Keep secrets out of UI and logs. Do not log secret values or send them to panels or webviews. Read and use them in your entry script (main.js) with tagline.network.fetch(). Network requests also require the reviewed network permission and the destination hostname in networkHosts.

Shortcuts and contributed themes

Mod+Alt+K uses the portable primary modifier. Valid modifiers include Mod, Ctrl, Meta, Alt, and Shift; use uppercase letter keys in manifests. Users can change or clear extension shortcuts in Settings > Keyboard shortcuts > Extensions. Malformed, reserved, or already-used defaults are dropped rather than overriding another command; the command remains available in the palette.

Theme-only extensions need no script or permissions:

{
  "manifestVersion": 1,
  "id": "ocean-themes",
  "name": "Ocean Themes",
  "version": "0.1.0",
  "contributes": { "themes": ["themes/ocean.json"] }
}

Theme IDs are assigned as ext:<extension-id>:<zero-based-file-index>. Keep the theme list order stable to preserve saved selections. See the Theme API for the theme file format and the JSON formats guide for schemas.

Keep exploring: Browse the API demo extension for working examples, or open the JSON schemas for manifests, themes, and exported settings.
