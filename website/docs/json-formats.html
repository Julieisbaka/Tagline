Supported formats

Tagline includes draft-07 JSON Schemas for its user-authored and exchanged formats. The schemas are maintained with the application source and can be downloaded for offline use.

Format Schema Where it is used
Speech flow (.flow) flow.schema.json Multi-sheet debate speech grids.
Extension manifest extension-manifest.schema.json Extension identity, entry points, contributions, and permissions.
Theme theme.schema.json Imported/exported themes and themes contributed by extensions.
Exported extension settings extension-settings.schema.json Settings exported for an extension.

Canvas files use the separate JSON Canvas 1.0 specification. Tagline stores them as .canvas files inside the vault.

Enable validation and completion in VS Code

The Tagline repository includes VS Code settings that associate speech flows, bundled/demo themes, extension manifests, and exported settings with their schemas. When working in another workspace, copy the schemas together and define matching json.schemas associations.

For example, this setting associates every .flow file in the workspace with a local copy of the flow schema:

{
  "json.schemas": [
    {
      "fileMatch": ["*.flow"],
      "url": "./schemas/flow.schema.json"
    }
  ]
}

Set .flow files to the JSON language mode if VS Code does not recognize them. Keep the schemas in the same relative layout when copying the folder: the theme and extension-settings schemas reference definitions in the extension-manifest schema.

Reference a schema from a file

Alternatively, add a $schema property near the top of a JSON document. This example assumes the JSON file sits beside a schemas folder:

{
  "$schema": "./schemas/flow.schema.json",
  "version": 1,
  "sheets": [
    {
      "name": "Case",
      "columns": ["1AC", "1NC"],
      "rows": [["Claim", "Answer"]]
    }
  ]
}

References are relative to each schema's location rather than an absolute remote ID, so a copied schema folder can be used offline. Some application import/export paths normalize files; do not rely on $schema being retained by every exporter.
